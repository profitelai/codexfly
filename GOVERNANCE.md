# Governance

## Project Model

Codexfly is maintained as an open-source project with maintainer review on changes to the default branch.

## Roles

### Maintainers

Maintainers can:

- review and merge pull requests
- manage labels, milestones, and roadmap direction
- update repository settings, branch protections, and contributor access

### Contributors

Contributors can:

- open issues
- propose pull requests
- improve code, documentation, and design

Trusted contributors may be granted direct `write` access, but should still work through pull requests.

## Decision Process

- small changes can be merged after maintainer review
- larger architectural changes should be discussed in issues or pull requests before implementation
- security-sensitive changes should follow [SECURITY.md](./SECURITY.md)

## Merge Policy

- `main` is the protected default branch
- changes should land through pull requests
- contributors should keep changes scoped and reviewable

## Ownership

The initial code ownership and final merge authority remain with the repository owner and maintainers until the maintainer group is expanded.
